# 多会话与设置

两个 CLI 共用会话与导航逻辑，样式完全独立，各自使用对应 App 的控件和样式。Claude 模式只激活三份 Claude 样式表，不继承 ChatGPT／Codex 的 palette、布局、会话行或设置样式。左上角默认是当前 CLI 的圆形图标（OpenAI 或 Claude 花形标志），点击直接打开近期会话，无中间导航层；鼠标悬停时展开左 OpenAI、右 Claude 的胶囊，移入对应标志即切换 CLI，无需点击，也不弹出切换下拉菜单；悬停期间保持原位展开，移开后收起，焦点不会保持展开。顶栏保留固定的空间与尺寸，切换时标题和按钮位置不变。中间显示当前标题，超长时末尾省略；右侧图标新建会话。菜单左对齐，最大宽度 280px；打开的会话、本机历史和 Codex 原生历史统一按完整项目路径分组、去重并按更新时间排序，显示已加载数量。历史缺少项目元数据时显示“未归属项目”，不猜测路径。工作样例仅从设置 → 调试与样例打开，不加入近期会话。

项目行和会话行使用已安装 Codex App 的原生侧栏行组件及样式。菜单标题与搜索框固定，列表单独滚动；滚轮在边界和标题处被消费，不传给背后的对话。原生历史使用跨项目分页查询，加载更多后继续合并分组。打开跨项目历史时保留实际工作目录，后续 CLI 任务使用该会话自己的工作目录。独立对话页没有常驻会话浏览栏和右侧消息导航条；设置在原侧栏内切换，没有嵌套窗口。

每个会话保存自己的消息、模型、推理强度、权限偏好、输入草稿和滚动位置。切换会话不清空内容；“新建”创建新会话。运行中的会话需先停止才能关闭。最多打开的会话数量可在“设置 → 会话”调整。

当前运行时共用一条 CLI 执行通道，因此任务按提交顺序执行：一个会话运行时，其他会话可阅读、输入和提交，待执行任务显示“排队中”。前一任务结束后自动开始下一任务。取消排队只移除该会话的待执行请求。运行中的配置不因另一会话切换模型而立即重启，下一次启动任务时应用对应会话的配置。

设置分类为常规、外观、会话、输入、Codex、Claude Code、上下文和诊断。设置控件继续使用真实保存和 CLI 配置入口。外观提供正文字号；设置搜索位于分类菜单内。

## 实现边界

- `src/sidebar-shell.js`：紧凑顶栏与多会话菜单。
- `src/sidebar-workspace.js`：原位设置页面和分类菜单。
- `src/claudian-sidebar-react.js`：会话状态、独立草稿、执行队列、配置快照和后台事件路由。
- `src/sidebar-workspace.css`：原位设置页面样式。

会话摘要和草稿本机缓存；原生 CLI 历史只缓存索引，完整消息按需读取，避免长对话挤满本机缓存后触发全部重置。重启不自动重新发送未完成任务。
