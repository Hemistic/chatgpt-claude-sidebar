# 2026-11-04 审批、提问和计划真 token 复验

本轮完成 23 个真实模型回合：Claude 20 个（全部 claude-haiku-5-5 / high），Codex 3 个（gpt-6.1-sol / high）。另有 3 个 Claude 计划回合未完成（一次窗口退出、两次审批防误触拦截后超时），不计通过。原始用量事件保留在报告中；不将重复累计事件相加，不把缺失用量记成零。

## 产品修复

- Codex 同一个编排调用包含修改文件和执行命令时，命令可能位于下一个可视记录组。现在以本轮命令记录核对包装调用，补丁仍在原编辑组匹配，消除重复编辑行，并保留独立的原生命令与多次编辑。
- Claude 原生 ToolStep 的 meta 是第二列详情。CLI 只提供同名工具摘要时不再重复传入，修复 EnterPlanMode / ExitPlanMode 的重复文字；未改原生控件声明或配色。

## 真实覆盖

- Claude：允许一次、拒绝、持续允许；问题多选、分页、中文其他答案、跳过；计划修改、拒绝、普通批准、允许编辑。检查计划内容、360/800 宽度及明暗主题。
- Codex：生成计划、展开/折叠、批准实施；批准后退出计划模式；真实修改与命令结果。独立执行四个边界断言。首次计划阶段有工具命令失败，模型随后恢复，原始错误保留。
- 修复后的 Codex 追加修改回合只显示一行文件编辑，命令记录仍保留。Claude 截图确认工具名称无重复。
- 相关自动化回归 28/28 通过。它们是补充检查，未替代真实调用。

## 测试驱动修复与异常

- 更新 Codex 计划测试的入口为真实 Shift+Tab 模式切换，完整结果要求实际 usage，并正确写入 report.ok。
- Claude 旧计划选择器改为当前原生计划套件；可选择单项计划复验。
- 一次窗口退出导致未完成，保留中断报告，不推断退出原因；测试报告在截图失败时保留原始异常。
- 一次批准按键未生效，补发后恢复；改成 Chromium 按键投递后，独立复验仍未触发批准。继续查原生 shared-26 的 Ly/Ry 与 Ty/_y，确认其 400ms 防误触机制要求近期可信交互，窗口获焦后的 1000ms 内输入也会被忽略，程序设置焦点不算真实输入。保留原机制，测试改为先等待 1200ms、点击卡片标题、等待 650ms，再发快捷键，发送时不重新激活窗口。多行反馈、清空反馈在前一轮实际通过；最终批准回合检查恢复普通权限和真实 Read 完成。
